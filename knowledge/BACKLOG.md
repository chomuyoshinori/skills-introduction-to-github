# 知識化バックログ(BACKLOG)

蔵書のトリアージ台帳。「読みたい本」ではなく **「仕事に効く本」から知識化する** ための待ち行列。
知識化(`/knowledge`)の入口を管理し、完成後は `knowledge/INDEX.md`(復習管理)と
仕事への適用(`/apply` で道具化)まで追いかける。

> 役割分担: **BACKLOG = 何を知識化するか(前工程)** / **INDEX = 知識化したものを忘れないか(後工程)**

## 3つの目的(知識化を仕事に反映する軸)
1. **個人事業主としての思考方法** — 意思決定・時間/資金/リスク管理・事業の回し方
2. **商品開発・マーケティング** — 企画→検証→販売、SNS/ネット販売含む
3. **AI能力の引き出し方** — プロンプト・AIエージェント活用・業務への組み込み

## 使い方
0. **パスの基準**: 表のパスは claude-lab(`claude` を起動するフォルダ)起点。`/knowledge "書籍/<フォルダ>/<書名>.pdf"` の形で実行する。
1. 知識化したい本をこの表に追加する(優先度・目的・期待する反映先を必ず付ける)。
2. Aの先頭から `/knowledge` を実行 → 完成したら状態が「ノート化済」になる(`knowledge/INDEX.md` にも登録される)。
3. ノートの内容を実際の仕事(プロンプト・チェックリスト・業務手順・発信テンプレ)に落とし込んだら「適用済」にする。**ノート化して終わりにしない。**(通常は `/apply <テーマ>` を実行すると道具化と状態更新が自動で行われる)
4. ペースは **週1〜2冊** を想定。詰め込みすぎると復習(`/knowledge-review`)が回らなくなる。
5. A枠は **常に4〜6冊以内** に保つ。増えたら入れ替え(BかCへ降格)する。

## 凡例
- **優先度**: A=今の仕事に直結(4〜6冊まで) / B=次の四半期に効かせたい / C=いつか(必要になったら昇格)
- **目的**: 1/2/3 = 上記「3つの目的」の番号。複数該当は併記(例: 2・3)
- **状態**: `未` → `ノート化済`(knowledge/ にノートあり)→ `適用済`(仕事の仕組みに反映した。通常 `/apply` が更新)
