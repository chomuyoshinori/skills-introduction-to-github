# iCloud写真 → Mac mini(Immich)移行ガイド

方針: **Mac mini(Immich)を写真の「正」とし、検証が終わったら iCloud写真を解約する。**

> ⚠️ **大原則(これだけは絶対に守る)**
> 1. **iCloud写真をオフにするのは、検証ゲート(STEP 3)を通過してから。** 「ストレージを最適化」中の iPhone には縮小版しかなく、原本は iCloud にしかない。順序を誤ると原本を失う。
> 2. **バックアップ(Time Machine)が1周してから解約する。** 解約後は Mac mini が唯一の原本置き場になる。
> 3. **1〜2ヶ月は並走させる。** 急いで解約しても得られるのは数百円。失うものは取り返せない。

## 全体の流れ

```
STEP 0  土台(Immich・SSD・バックアップ・Tailscale)← README.md の Phase 0
STEP 1  新規写真の自動バックアップ開始(iPhone → Immich)
STEP 2  過去分の一括移行(iCloud → Mac mini 写真App → Immich)
STEP 3  ★検証ゲート(枚数照合・実物確認・バックアップ1周)
STEP 4  iCloud写真をオフ(iPhone → Mac の順)
STEP 5  プラン見直し・定常運用へ
```

---

## STEP 1 — 新規写真の自動バックアップ開始(初日)

- [ ] iPhone に Immich アプリ → 自動バックアップ ON(まずは Wi-Fi のみ推奨)
- [ ] 以後に撮る写真はこの時点から安全になる。過去分の移行(STEP 2)と並行して進む

> この段階では iPhone の「アップロード済みを端末から削除」は**まだ実行しない**
> (「ストレージを最適化」中の端末なら、そもそも端末側は縮小版なので急ぐ必要がない)。

## STEP 2 — 過去分の一括移行(数日〜、放置作業)

iPhone アプリ経由でも原本は移行できるが、膨大なライブラリでは iCloud からの
原本ダウンロードを1枚ずつ行うため遅くて不安定。**Mac mini の写真App で一括ダウンロード**するのが確実。

- [ ] **写真ライブラリを外付けSSDに作る**: `option` キーを押しながら 写真App を起動 →
      「新規作成」で外付けSSD上にライブラリ作成 → 設定 → 一般 →「システム写真ライブラリとして使用」
- [ ] 写真App → 設定 → iCloud → 「iCloud写真」ON + **「オリジナルをこのMacにダウンロード」**を選択
- [ ] 完了まで放置(数万枚なら数日)。進捗はライブラリ最下部の「◯◯枚の写真・◯本のビデオ」と
      ダウンロード状況表示で確認。SSD の空きは**ライブラリ想定サイズの2倍以上**確保しておく(書き出し分)
- [ ] 全件ダウンロード完了後、**全選択(⌘A)→ ファイル → 書き出す → 「◯◯枚の写真の未編集のオリジナルを書き出す」**
      (IPTC を XMP として書き出すにチェック)→ SSD上の作業フォルダへ
- [ ] **Immich へ取り込み**(Mac mini 上で):
      ```bash
      npm i -g @immich/cli
      immich login http://localhost:2283 <APIキー>
      immich upload --recursive <書き出したフォルダ>
      ```
      Immich はファイルハッシュで重複を自動スキップするため、**STEP 1 で iPhone から
      既にアップロード済みの分と二重にはならない**。

### 書き出し漏れに注意(見落としがちな場所)

- [ ] 「**非表示**」アルバムと「**最近削除した項目**」の中身を確認(全選択に含まれないことがある)
- [ ] **共有アルバム**・iCloud共有ライブラリの写真は自分のライブラリに含まれない。残したいものは先に「保存」
- [ ] **編集済み写真**: 「未編集のオリジナル」書き出しでは編集(トリミング・調整)が反映されない。
      編集を大事にしている写真だけ、別途「写真を書き出す」(編集後の状態)も実行して両方取り込む

## STEP 3 — ★検証ゲート(ここを通過するまで iCloud に触らない)

- [ ] **枚数照合**: 写真App の「写真◯枚・ビデオ◯本」と Immich の管理画面 → サーバー統計を比較。
      (Live Photos の動画部分や重複スキップで数十件の誤差は出得る。誤差の理由を説明できればOK)
- [ ] **実物確認**: ①最古の写真 ②ランダムに10枚 ③RAW数枚(拡大して原寸確認)④長めの動画1本の再生
- [ ] **Time Machine バックアップが1周完了**(SSD の Immich ライブラリが対象に含まれていること)
- [ ] (推奨)オフサイト第3コピー(Backblaze B2 等へ暗号化アップロード)
- [ ] Sift でスキャン実行 → 件数が Immich と整合していること

## STEP 4 — iCloud写真をオフ(検証通過後)

- [ ] **iPhone**: 設定 → [自分の名前] → iCloud → 写真 → 「このiPhoneを同期」をオフ。
      ダイアログは「iPhoneから削除」を選んでよい(原本は Immich にあると検証済みのため。
      「写真とビデオをダウンロード」は端末容量を食うだけなので選ばない)
- [ ] **Mac mini**: 写真App → 設定 → iCloud → 「iCloud写真」オフ。
      SSD上の写真ライブラリは**すぐ消さない**(数ヶ月は第2のアーカイブとして保持。
      Immich 運用が安定したら削除して容量回収してよい)
- [ ] iPhone の Immich アプリで「アップロード済みをデバイスから削除」を実行 → 端末容量が空く

## STEP 5 — プラン見直しと定常運用

- [ ] **1〜2ヶ月並走後**、問題なければ iCloud+ プランをダウングレード。
      **注意: iCloud ストレージは iPhone本体のバックアップ(設定・メッセージ等)にも使われている。**
      - 節約重視: 50GB(月額最安)だけ残して本体バックアップ用にする ← 推奨
      - 完全無料化: iPhone を月1回 Mac mini にケーブル接続し Finder でバックアップする運用に変更
- [ ] 定常運用: 撮影 → 自動バックアップ(全自動)/ 月1回 Immich アプリで端末から削除(2タップ)/
      すきま時間に Sift で選別

## リスクと対処

| リスク | 対処 |
|---|---|
| 原本がダウンロードし切れていないのに iCloud を切る | STEP 3 の検証ゲートを通過するまで STEP 4 に進まない(このガイドの存在理由) |
| 移行中に Mac mini / SSD が故障 | iCloud を切る前なら原本は iCloud に残っている。だから「検証→バックアップ→解約」の順 |
| Live Photos が静止画+短い動画に分かれて見える | 実害なし(原本は両方保存されている)。Immich はメタデータで再ペアリングを試みる |
| 解約後に iCloud 側の写真が消える | 想定通りの動作。だからこそ解約は最後、並走期間を設ける |
