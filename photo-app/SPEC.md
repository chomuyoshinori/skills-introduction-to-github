# 写真選別アプリ「Sift(仮称)」仕様書 v1.0

Immich(自宅サーバー)上の写真ライブラリを対象に、**不要な写真の発見 → 比較 → 迷わない削除**
を支援する個人用 Web アプリの仕様書。名称は「ふるいにかける」の意の *sift* から(仮称・変更自由)。

- 対象読者: 本アプリを実装する開発者(Claude Code を含む)
- 前提: [README.md](./README.md) の Phase 0(Immich + Tailscale + バックアップ)が完了していること

---

## 1. 目的と背景

| 課題 | 本アプリの解決 |
|---|---|
| 写真が膨大でスマホ容量が逼迫(RAW含む) | (Immichが解決)母艦へ自動退避・端末から解放 |
| スクショ・画面メモ・一時的なメモ写真が堆積する | 自動検出して「候補」として提示。まとめて流れ作業で処分 |
| 重複・類似・連写が多い | グループ化し、ベストショットを自動提案。残り一括削除 |
| 削除は「考えるのが面倒」で先送りになる | 1画面1判断のスワイプUI・即Undo・遅延実行で心理的負担を最小化 |

### 非目標(やらないこと)
- 写真の保存・同期・閲覧・検索そのもの(Immichの領分。二重実装しない)
- **全自動削除**。候補提示と一括操作は自動化するが、削除の最終判断は必ず人間が行う
- 複数ユーザー対応・共有機能(個人利用専用)
- RAW現像・レタッチ(Lightroom等の領分)

## 2. 役割分担(スコープ境界)

| 機能 | Immich | Sift(本アプリ) |
|---|:-:|:-:|
| スマホ自動バックアップ・容量解放 | ● | |
| タイムライン閲覧・被写体検索・顔認識 | ● | |
| 完全重複(同一ハッシュ)検出 | ● | APIで結果を利用 |
| 類似・連写のグループ化 | △(類似検出あり) | ● 補完・独自グルーピング |
| スクショ/メモ写真/ぼやけ検出 | | ● |
| スワイプ選別・比較・ベスト提案UI | | ● |
| ゴミ箱(30日復元)・完全削除 | ● | APIで「ゴミ箱へ移動」までを実行 |

## 3. ユーザーストーリー

1. **夜のソファで5分**: スマホでSiftを開くと「スクショ142枚(約310MB)が候補です」。スワイプで
   テンポよく振り分け、最後に一覧確認して一括でゴミ箱へ。「今日は420MB解放」と表示される。
2. **旅行後の整理**: 同じ構図の連写・撮り直しが大量にある。Siftがグループ化して★ベスト案を提示。
   グループごとに「ベスト以外を削除予定へ」を押すだけ。気になるグループだけ2枚並べて拡大比較。
3. **不安なく削除**: 間違ってスワイプしても即Undo。削除はまずImmichのゴミ箱に入るだけなので、
   30日以内ならいつでも復元できる。

## 4. システム構成

```
[スマホ/PCのブラウザ(PWA)]
        │ HTTPS(Tailscale ネットワーク内のみ)
        ▼
[Sift サーバー(Mac mini 上)]
  ├ Web UI 配信(React ビルド成果物)
  ├ REST API(判断の記録・候補リスト提供)
  ├ 候補抽出ジョブ(夜間バッチ+手動実行)
  └ SQLite(選別状態・スコア・統計)※写真実体は持たない
        │ Immich REST API(localhost、APIキー認証)
        ▼
[Immich Server] ─ 写真実体(外付けSSD)/ サムネイル / ML(CLIP・顔)/ ゴミ箱
```

設計原則: **Sift は写真データを一切複製しない。** 画像表示は常に Immich のサムネイル/プレビュー
API を参照し、Sift が保持するのはアセットIDと判断状態・スコアのみ。壊れても写真は無傷。

## 6. 候補抽出エンジン

各シグナルを重み付きで合算し、閾値を超えたものをカテゴリ別の「候補キュー」に入れる。
**スコアはあくまで並び順と提案に使い、削除の自動実行には使わない。**

### 6.1 スクリーンショット / 画面メモ

| シグナル | 判定方法 | 重み |
|---|---|:-:|
| ファイル名 | `Screenshot` / `スクリーンショット` / `Screen Shot` 等のパターン | 高 |
| EXIF | カメラの Make/Model が無い | 中 |
| 形式・解像度 | PNG かつ 端末画面解像度(設定で登録)と縦横一致 | 高 |
| CLIP | Immich スマート検索 `screenshot of a phone screen` の類似度 | 中 |

### 6.2 メモ写真(書類・ホワイトボード・値札・駐車位置 等)

| シグナル | 判定方法 | 重み |
|---|---|:-:|
| OCR 文字量 | 文字領域の面積比が閾値超(Tesseract.js または macOS Vision) | 高 |
| CLIP | `document` / `whiteboard` / `receipt` / `price tag` 等の類似度 | 中 |
| 非お気に入り | Immich でお気に入り・アルバム所属が無い | 中 |
| 経過日数 | 撮影から30日以上(メモの賞味期限切れ) | 中 |

### 6.3 類似・連写グループ

- 同一カメラ・撮影時刻が近接(既定 ±5秒、設定可)→ 連写グループ
- Immich の類似検出結果+知覚ハッシュ距離 → 類似グループ
- グループ内ベスト提案スコア = シャープネス(ラプラシアン分散)+ 顔の有無/目つぶり
  (Immichの顔メタデータ利用)+ 露出ヒストグラム + 解像度 + お気に入りフラグ(最優先)

### 6.4 除外(セーフリスト)

以下は候補に**入れない**: お気に入り済み / ユーザーが「残す」判断済み /
アルバム所属(設定でON/OFF)/ 除外指定したフォルダ・期間。

## 8. UX/UI 仕様

### 8.1 デザイン原則

1. **1画面1判断** — 迷いの原因は選択肢の多さ。スワイプ中は他の情報を出さない。
2. **デフォルト提案** — 「何を消すか」をアプリが先に提案し、人は Yes/No だけ言う。
3. **常に後戻り可能** — 即Undo・遅延実行・ゴミ箱30日の三重防護(§9)。だから迷わず押せる。
4. **セッションは小さく** — 候補は50枚単位で区切り「あと◯枚」を見せる。5分で1セッション。
5. **成果の見える化** — 判断のたびに解放予定容量が増えるカウンタを表示。
6. **スマホ=親指、Mac=キーボード** — 主要操作は片手親指の可動域(画面下半分)に配置。

### 8.2 画面一覧

```
S-1 ホーム ─┬─ S-2 スワイプ選別(カテゴリ別キュー)
            ├─ S-3 グループ比較(類似・連写・重複)
            ├─ S-4 削除予定の確認(→ Immich ゴミ箱へ)
            └─ S-5 統計 / 設定
```

### S-1 ホーム(今日の整理提案)

```
┌──────────────────────────────┐
│ Sift            解放済み 12.4GB 🎉 │
│                                    │
│ 今日の提案                          │
│ ┌───────────┐ ┌───────────┐ │
│ │ 📱 スクショ      │ │ 🔁 類似・連写   │ │
│ │ 142枚 ≈310MB   │ │ 23組 ≈1.2GB   │ │
│ │ [整理する →]    │ │ [比較する →]   │ │
│ └───────────┘ └───────────┘ │
│ ┌───────────┐ ┌───────────┐ │
│ │ 📄 メモ写真     │ │ 🌫 ぼやけ      │ │
│ │ 67枚 ≈180MB   │ │ 31枚 ≈95MB    │ │
│ └───────────┘ └───────────┘ │
│                                    │
│ 🗑 削除予定 89枚 ≈420MB [確認して実行] │
└──────────────────────────────┘
```

- カテゴリカードには枚数と概算容量を必ず併記(押す動機になる)。
- 削除予定バッジは常時表示。溜まっていることを忘れさせない。

### S-2 スワイプ選別

```
┌──────────────────────────────┐
│ ✕閉じる   スクショ  12/50   +82MB 🗑 │
│ ┌────────────────────────┐ │
│ │                            │ │
│ │        [写真プレビュー]        │ │
│ │   (タップで拡大・ピンチズーム)    │ │
│ │                            │ │
│ └────────────────────────┘ │
│  2025/11/03 ・ PNG ・ 2.1MB ・ 未整理  │
│                                    │
│   ← 削除予定      残す →            │
│   ↑ お気に入り     ↓ あとで          │
│                                    │
│  [🗑]   [↩︎ 元に戻す]   [♡]   [✓]   │
└──────────────────────────────┘
```

- ジェスチャ: 左=削除予定 / 右=残す / 上=お気に入り(Immichに反映)/ 下=あとで(キュー末尾へ)。
  下部ボタンでも同操作可(片手・電車内向け)。
- スワイプ直後に小さなUndoトースト(3秒)。連打しても1つずつ戻せる(操作履歴スタック)。
- キーボード(F-11): `J`=削除予定 `K`=残す `F`=お気に入り `S`=あとで `Z`=Undo `Space`=拡大。
- 50枚ごとに完了画面「このセッションで +82MB 解放予定 / 続ける・終わる」。

### S-3 グループ比較(類似・連写・重複)

```
┌──────────────────────────────┐
│ ← 類似グループ 4/23     [残りは全部OK] │
│ 「2025/10/12 のよく似た4枚」            │
│ ┌─────┐┌─────┐┌─────┐┌─────┐│
│ │ ★ベスト ││      ││      ││      ││
│ │  提案   ││      ││      ││      ││
│ └─────┘└─────┘└─────┘└─────┘│
│  タップ=ベスト変更 / 長押し=2枚比較      │
│                                    │
│ [★以外の3枚を削除予定へ]  [全部残す]    │
└──────────────────────────────┘
```

- 既定操作は「★以外を削除予定へ」ボタン1つ。**グループ単位で1判断**にする。
- ★はスコア(§6.3)による自動提案。別の写真をタップすると★が移る。
- 長押しで **A/B比較モード**: 2枚を並べ、ピンチ拡大が両方に同期(Lightroom流)。顔・文字のピント確認用。
- 完全重複(同一ハッシュ)グループは「1枚だけ残して他を削除予定へ」を既定にし、
  Apple写真の「結合」に倣いメタデータ(アルバム所属・お気に入り)が最も豊富な1枚を残す。

### S-4 削除予定の確認(実行ゲート)

```
┌──────────────────────────────┐
│ 削除予定 89枚 ≈420MB               │
│ ▼ 11月 (34枚)  [サムネ一覧…]        │
│ ▼ 10月 (55枚)  [サムネ一覧…]        │
│  ※タップで個別に取り消しできます        │
│                                    │
│ [🗑 89枚をゴミ箱へ移動]              │
│  Immichのゴミ箱で30日間復元できます     │
└──────────────────────────────┘
```

- ここで初めて Immich API を呼び「ゴミ箱へ移動」する。完全削除は行わない(Immich側の30日自動削除に任せる)。
- 実行後トースト: 「420MB分をゴミ箱へ移動しました [元に戻す]」(一括復元、60秒有効)。

### S-5 統計 / 設定

- 統計: 累計解放容量、レビュー済み枚数、カテゴリ別の残り候補、月別グラフ。
- 設定: 端末画面解像度の登録(スクショ判定用)、連写判定の秒数、アルバム所属を除外するか、
  自動ルール(F-10)のON/OFF、Immich接続情報。

### 8.3 ビジュアルトーン

- ダーク基調(写真が主役。Immich/Lightroomと同様に背景は無彩色の濃灰)。
- 削除系アクションは赤を使わず**グレー+ゴミ箱アイコン**(赤は「取り返しがつかない」圧を与え、
  テンポを削ぐ。実際ゴミ箱行きで取り返しがつくため)。完全削除ボタンのみ赤。
- アニメーションはスワイプの物理挙動のみ丁寧に(慣性・回転)。他は最小限。

## 9. 安全設計(誤削除防止の三重防護)

1. **即Undo** — スワイプ・一括操作の直後に取り消し可能(操作履歴スタック)。
2. **遅延実行** — 「削除予定」はSift内のキューに溜まるだけ。S-4の確認を通るまでImmichに一切書き込まない。
3. **ゴミ箱30日** — 実行しても Immich のゴミ箱に移動するだけ。完全削除は Immich の標準挙動に委ねる。

追加ルール:
- RAW+JPEG ペア(スタック)は必ずペア単位で扱い、片割れだけ消えることを防ぐ。UI上に「RAWペア」バッジを表示。
- お気に入り済みアセットへの削除操作は追加確認を出す。
- Sift の SQLite は毎晩バックアップ(判断履歴の消失防止)。

## 10. RAW データの運用方針

| ソース | 方針 |
|---|---|
| スマホの ProRAW / RAW | Immich アプリで RAW ごとバックアップ → 端末から解放。閲覧は Immich が生成する JPEG/サムネで軽快に。 |
| 一眼カメラの RAW | Immich の「外部ライブラリ」に取り込みフォルダ(外付けSSD)を登録。ファイルは移動されず、現像ソフトからも同じ実体を参照できる。 |
| Sift での扱い | RAW はサイズが大きいため削除候補の容量表示に効く。ただし §9 のとおりペア単位でのみ操作。 |

## 11. 非機能要件

| 項目 | 要件 |
|---|---|
| 規模 | 写真10万枚・グループ1万件で実用速度を維持 |
| 応答 | 候補一覧・スワイプ操作は体感即時(サムネは Immich のサムネイルAPIを利用し、次の10枚を先読み) |
| 抽出ジョブ | 夜間バッチ(launchd)+手動実行。初回フルスキャン後は増分のみ |
| セキュリティ | 待受は Tailscale ネットワーク内のみ(ポート公開しない)。Immich APIキーはサーバー側 `.env` のみに保持しブラウザへ渡さない。念のため簡易PINロック |
| プライバシー | 全処理をローカル(Mac mini)で完結。外部クラウドへ画像を送らない |
| 可搬性 | Sift が消えても写真・Immichは無傷(§4 の非複製原則) |

## 12. 技術スタック

| レイヤ | 採用 | 理由 |
|---|---|---|
| フロント | React + Vite + TypeScript + Tailwind CSS、PWA | スワイプUIの実装資産が豊富。PWAでスマホのホーム画面から起動 |
| サーバー | Node.js + Hono + better-sqlite3 | 軽量・単一プロセス。Mac mini に launchd で常駐 |
| 画像解析 | sharp(縮小・ラプラシアン)、Tesseract.js(OCR)。CLIP・顔・重複は **Immich の ML を API 経由で使い倒す** | 自前MLを持たない=保守が軽い |
| Immich 連携 | REST API(検索・アセット・重複・ゴミ箱・お気に入り) | エンドポイントはバージョン差があるため実装時に稼働中の `/api/docs`(OpenAPI)で確認し、**薄いクライアント層に隔離**する |
| 配置 | Immich と同じ Mac mini。docker compose に追加 or ネイティブ常駐 | localhost 通信で高速 |

### データモデル(SQLite・概略)

```sql
-- Immichのアセットに対する Sift 側の状態(写真実体・メタの複製はしない)
asset_state(
  asset_id TEXT PRIMARY KEY,       -- Immich asset id
  category TEXT,                   -- screenshot | memo | blurry | none
  score REAL,                      -- 候補スコア
  decision TEXT,                   -- keep | trash_pending | trashed | favorite | later | NULL(未判断)
  decided_at TEXT,
  group_id INTEGER
);
groups(id, kind /* duplicate|similar|burst */, best_asset_id, created_at);
sessions(id, started_at, reviewed_count, freed_bytes_estimate);
undo_log(id, action_json, created_at);      -- 操作履歴(Undoスタック)
settings(key, value);
```

### API 概略(Sift サーバー)

```
GET  /api/queues                     カテゴリ別の候補数・概算容量
GET  /api/queues/:category?cursor=   候補アセット(ページング、サムネURLはImmichへのプロキシ)
POST /api/decisions                  { assetIds, decision }  判断の記録
POST /api/undo                       直前操作の取り消し
GET  /api/groups?kind=similar        グループ一覧(ベスト提案含む)
POST /api/groups/:id/keep-best       ★以外を trash_pending へ
POST /api/trash/commit               削除予定を Immich ゴミ箱へ移動(唯一の書き込み系Immich呼び出し)
POST /api/jobs/scan                  候補抽出ジョブの手動実行
GET  /api/stats                      統計
```

## 13. リスクと対策

| リスク | 対策 |
|---|---|
| Mac mini / SSD 故障で写真全損 | Phase 0 で 3-2-1 バックアップ(本体SSD+Time Machine先HDD+可能ならBackblaze B2等へ暗号化第3コピー) |
| Immich のAPI破壊的変更 | docker compose でバージョン固定。Immichクライアント層を1ファイルに隔離。アップデート前にリリースノート確認 |
| 検出の誤判定(大事な写真が候補に) | 自動削除を一切しない設計(§5)+三重防護(§9)+セーフリスト(§6.4) |
| 選別が続かない(飽きる) | 50枚セッション・容量カウンタ・ホームの提案カードで「5分でできる」体験を維持 |
| スマホがiPhoneかAndroidかの差 | Immichアプリが両対応のため Sift 側は影響なし。スクショ判定の画面解像度のみ設定で登録 |
