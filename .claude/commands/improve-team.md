チームの自己改善ループを実行してください。`LESSONS.md` に蓄積された「手順書の改善提案(未適用)」を実際の変更に変換し、**人間がレビューできるPR**として提出します。

## 大原則
- **自分でマージしない**。最終判断は必ず人間(PRレビュー)に残す。
- 提案がない・すべて適用済みなら、その旨を報告して終了する(無理に変更を作らない)。

## 手順
1. `LESSONS.md` の「## 手順書の改善提案(未適用)」セクションを読む。空なら終了。
2. 各提案について対象ファイル(`.claude/agents/*.md` / `.claude/commands/*.md` / `TEAM_STANDARDS.md` 等)の現状を読み、提案が現在も有効か確認する(すでに別の変更で解消済みなら「適用不要」として処理)。
3. 新しいブランチ `team-improvement-YYYY-MM-DD` を作成し、有効な提案を適用する。
4. **整合性チェック**: 変更が `TEAM_STANDARDS.md`(共通規律の原本)と矛盾しないか、確信度4段階・ファイルパス規約・用語(未確認/要確認)が保たれているかを自分で点検する。修正が大きい場合は `red-team-critic` に変更差分を検証させる。
5. `LESSONS.md` の適用した提案を「## 手順書の改善提案(適用済み)」へ移動し、適用日とブランチ名を付記する(この変更も同じブランチに含める)。
6. コミットしてプッシュし、PRを作成する(タイトル例: 「チーム手順書の改善: 〜」。本文に: 元になった教訓 / 変更内容 / 期待する効果)。PR作成手段がない環境ならブランチをプッシュし、PR作成用のURLと本文案をチャットに提示する。
7. **チャット報告**: 適用した提案の一覧 / 見送った提案と理由 / PRのURL(または作成手順)。

## 注意
- 1回の実行で扱う提案は最大5件まで(レビュー可能な粒度を保つ)。多い場合は影響の大きい順に選ぶ。
- 動作を変える提案(cron時刻・モデル変更・ツール権限)は、PR本文でコスト・リスクへの影響を必ず明記する。
- このコマンドは対話環境での実行を想定(自動実行のスケジュール対象にしない)。
