第25回 日本PTEG研究会 学術集会のプロモーション企画を、プロモーションチームで作成してください。

## 手順
1. まず以下を読み、前提と教訓を踏まえる:
   - `pteg-promotion/PROMO_PROFILE.md`(開催概要・ストーリー・**表現ルール**)
   - `pteg-promotion/PROMO_LESSONS.md`(教訓)
   - `pteg-promotion/PROMO_DECISION_LOG.md`(過去の決定)
   - `pteg-promotion/CHALLENGES.md`(挑戦バックログ)
2. `$ARGUMENTS` を解釈する:
   - テーマ・範囲の指定あり(例: `/pteg-plan 演題募集の告知計画`)→ 関係する部署だけ起動する**軽量モード**でよい。
   - 指定なし → 年間プロモーション全体計画として全部署を起動。
3. 関係する部署エージェントを**並行して**起動する(全体計画なら全6部署):
   - `pteg-strategy-planner` → 全体戦略・ターゲット・KPI・逆算スケジュール
   - `pteg-marketing-pr` → チャネル計画・告知カレンダー
   - `pteg-creative-director` → クリエイティブ方針・制作物ドラフト(→ `pteg-promotion/deliverables/`)
   - `pteg-engagement-lead` → 演題募集・参加登録・参加者体験
   - `pteg-insight-analyst` → 他学会ベンチマーク・案の比較評価・KPI測定設計
   - `pteg-innovation-lead` → 挑戦枠の提案(最低1件、仮説/実験/成功基準/撤退基準つき)
   各エージェントには社長の指示(`$ARGUMENTS`)とプロファイル・教訓の要点を渡す。
4. 全出力を `pteg-vice-president` に渡して**批判的検証**を行わせる(必須ゲート。軽量モードでも飛ばさない)。重大な差し戻しは該当部署に1回まで再依頼してよい。
5. `pteg-secretariat` に全出力+副社長の指摘を渡して統合させ、`pteg-promotion/proposals/YYYY-MM-DD-<テーマ>.md` に保存、`pteg-promotion/PROMO_DECISION_LOG.md` に見立て・KPI・反証条件・検証予定を追記させる。
6. 最後にチャットへ要約する:
   - ① 提案の要点 ② 挑戦枠の内容 ③ **副社長の重大な指摘と、社長指示への上申・対案(あれば必ず明示)** ④ 社長の決定が必要な事項

## 注意
- 表現ルール(`PROMO_PROFILE.md` §3)への違反がないか、副社長検証で必ず確認させる。
- 提案には必ず複数案+比較+推奨を含める。挑戦枠のない提案書は完成と見なさない。
- 社長の指示より良いと考える案があれば、指示通り案と並記して理由付きで上申する(勝手に置き換えない)。
- 未確定情報(参加費・演題募集時期など)は憶測で埋めず「要確認」と明記し、社長への確認事項に集約する。
