書籍知識化チームを使って、蓄積済みの知識ノートを「仕事で使える道具」に変換してください(知識→行動変換)。読んで理解した知識を、個人事業の実務でそのまま使える形に落とすのがこのコマンドの役割です。

## 入力
- 対象: `$ARGUMENTS`(テーマ / 書名 / 仕事の課題。例: `/apply 新商品の価格決め`)。指定がなければユーザーに「いま仕事で困っていること・道具にしたいテーマ」を尋ねる。
- 作る道具が**ユーザーの3つの目的のどれに効くか**を必ず特定する(複数該当も可):
  1. **個人事業主としての思考方法**(意思決定・時間/資金/リスク管理・事業の回し方)
  2. **商品開発・マーケティング**(企画→検証→販売、SNS/ネット販売含む)
  3. **AI能力の引き出し方**(プロンプト・AIエージェント活用・業務への組み込み)

## 手順
1. `KNOWLEDGE_PROFILE.md` と `KNOWLEDGE_LESSONS.md`(あれば)を読み、読者像・用途・過去の教訓を踏まえる。
2. `knowledge-librarian`(司書)を起動し、課題に関連するノートを `knowledge/INDEX.md`(台帳)→ `knowledge/*.md` の順で横断検索させる。キーワードは言い換え・関連語に展開し、**出典付き**(どのノートのどこが課題に効くか)で報告させる。
   - 関連ノートが1件も見つからない場合はここで止め、「まず `/knowledge` で該当書籍を知識化する」ことを提案する(**出典なしで道具を作らない**)。
3. `knowledge-engineer`(企画/エンジニア)を起動し、司書の検索結果を**課題に合う形式の実務の道具**に変換させる。形式は課題の性質に応じて選ぶ(組み合わせも可):
   - **チェックリスト** — 抜け漏れ防止(例: 発売前の最終確認)
   - **テンプレート** — 繰り返し作業の型(例: 商品企画シート、SNS投稿の骨子)
   - **判断基準** — 迷ったときの物差し(例: 価格決定の基準表、外注する/しないの基準)
   - **手順書** — 一連の流れの標準化(例: 企画→検証→販売のステップ)
4. 道具の各項目には**根拠となるノートの出典**(`〔出典: knowledge/○○.md〕`)を付けさせる。ノートに無いが実務上必要で補った部分は **`〔補完〕` と明示**させる(この時点で裏取りは不要。裏取りは次の検証ゲートで行う)。補完だらけになるならノート不足のサインなので、`/knowledge` での追加知識化を提案する。
5. `knowledge-critic`(批判的副リーダー)に **必ず** 渡し、以下を検証させる(必須ゲート):
   - **実行可能性**: 個人事業主が一人で実際に回せるか。抽象論・べき論で終わっていないか。所要時間や前提リソースは現実的か。
   - **根拠**: 各項目に出典があるか。ノートの内容を歪めたり、文脈を無視して都合よく流用していないか。
   - **補完の裏取り**: `〔補完〕` 項目を WebSearch / WebFetch で裏取りする(出典・時点を付す。裏が取れなければ「未確認」と明記させる)。
   - **著作権・断定**(倫理観点をこのゲートに含める): 本文の丸写しがないか、引用は短く出典明記か、断定の行き過ぎがないか。
   - **抜け**: 課題に対して重要な観点が落ちていないか。適用限界・例外・「使ってはいけない場面」が示されているか。
6. 指摘を反映した完成版を `knowledge/applied/<テーマ>.md` に保存する(下記フォーマット)。
7. `knowledge/BACKLOG.md`(あれば)を確認し、今回の元ノート・テーマに対応する行があれば状態を**「適用済」**に更新する(該当行が無ければ何もしない)。
8. 最後にチャットへ「道具の一言サマリー」「使うときの最初の一歩」「批判的検証で残った留意点」を要約する。

## 保存フォーマット(`knowledge/applied/<テーマ>.md`)
```
---
title: 〔道具の名前〕
目的: 〔1/2/3 のどれに効くか + 一言(例: 2. 商品開発 — 価格決定の判断材料)〕
元ノート: [knowledge/○○.md, knowledge/△△.md]
作成日: YYYY-MM-DD
tags: [価格, 商品開発, ...]
---

## この道具が解決する課題
（どんな場面で取り出して使うか。1〜3行）

## 道具本体
（チェックリスト/テンプレート/判断基準/手順書。各項目に出典を付す）
- [ ] 〜 〔出典: knowledge/○○.md — 該当箇所の要点〕
- [ ] 〜 〔補完: ノートに無いため追加。根拠: Web出典・時点 / 未確認なら「未確認」と明記〕

## 適用限界・使ってはいけない場面
- 〜（元の本の前提が成り立たないケース、規模・業種による例外）

## 批判的検証で残った留意点
- 〜（副リーダーの指摘のうち、使うたびに思い出すべきもの）
```

## 注意
- **道具は判断材料であり、事業の意思決定はユーザー自身が行う。** 特に価格・投資・契約などの重要判断について「必ず〜すべき」と断定しすぎない。確信度と前提条件を添える。
- **出典なしで道具を作らない。** ノートに無い部分は `〔補完〕` と明示し、未確認は未確認と書く。記憶や推測でノートの内容を捏造しない。
- 書籍本文の丸写しをしない。道具はノートの**要約・再構成**であり、引用は短く出典明記(既存の著作権ルールに従う)。
- 批判的検証(必須ゲート)を通っていない道具は保存しない。
- 道具は作って終わりではなく、**使って改善する**。実際に使った結果・気づきは `KNOWLEDGE_LESSONS.md` に追記し、道具ファイル(`knowledge/applied/<テーマ>.md`)自体も必要に応じて更新して育てる(道具の frontmatter の作成日はそのまま、更新履歴を本文末尾に残す)。
