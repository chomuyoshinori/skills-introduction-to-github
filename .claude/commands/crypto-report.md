暗号資産(別枠「高リスク」)のリサーチレポートを、リサーチ・分析チームを使って作成してください。

## 手順
1. **日付の確定**: 今日の日付(JST)を確認し、`DATE=YYYY-MM-DD` とする(暗号資産は24時間市場のため、価格には必ず取得時点を付けさせる)。作業ディレクトリ `reports/work/crypto-DATE/` を使う。
2. **前提の読み込み**: `CRYPTO_PROFILE.md`(高リスク枠・保有数量)と `LESSONS.md` を読む。`DECISION_LOG.md` の [CRYPTO] タグから「検証予定」期日到来の未検証項目(特にアンロック日)を宿題リストとして控える。
3. `crypto-analyst` を起動する(出力先: `reports/work/crypto-DATE/crypto.md`)。プロンプトに「今日の日付」「出力先」「宿題」を含め、以下を分析させる:
   - 地合い: BTC価格・ドミナンス、ETH、Fear&Greed、ETFフロー(週次)、マクロ(米金利・ドル)、サイクル局面
   - 個別: `$ARGUMENTS` に銘柄指定があればそれを対象に。なければ CRYPTO_PROFILE.md の保有銘柄全て(概算ウェイト順に深掘り)
   - 各銘柄でトークノミクス・次回アンロック(日付・数量・供給比)・規制・固有リスクを必ず確認
4. **レッドチーム検証(必須ゲート)**: `red-team-critic` に出力ファイルを読ませて検証させる(出力先: `reports/work/crypto-DATE/redteam.md`)。特に「保有銘柄の相関(アルトはBTC/リスク選好に連動して同時に動く=分散の錯覚)」「アンロックの崖(スケジュール数量と実流通の区別)」「新興L1・ミームの投機性」「TVL等の分母トリック(ドル建て基準)」を重点検証させる。
5. **差し戻しループ(最大1回)**: 重大なデータ誤りがあれば crypto-analyst に1回だけ修正させる。収束しなければ未解決論点として編集長に渡す。
6. **統合**: `report-editor` に作業ディレクトリの全ファイルを読ませて統合 → `reports/crypto-DATE.md` に保存、主要な見立てを `DECISION_LOG.md` に「[CRYPTO]」タグ付きで追記、「未解決の宿題」セクションを設けさせる。
7. **完了確認**: `reports/crypto-DATE.md` と DECISION_LOG.md 追記を確認する。
8. **チャット報告**: 「今日の要点(3行)」「最も注意すべき点」「直近のアンロック・規制イベント予定」を要約する。

## 注意
- 暗号資産は高リスクで全額を失う可能性がある旨を、レポート冒頭に必ず明記する。
- 価格は24時間で大きく動くため、必ず取得時点を明記し、未確認は断定しない。
- 株式の「中リスク」基準を流用せず、高リスク枠として評価する。
- `reports/work/` は中間成果物置き場(コミット対象外)。
