`書籍/` フォルダに散在する書籍PDFを、管理しやすいフォルダ構成に整理してください。
**ユーザーの承認を得るまで、ファイルを1つも動かさないこと。**

## 入力
- 対象: `$ARGUMENTS`(特定フォルダの指定があればそこだけ。例: `/organize-books 書籍/PC・デザイン`)。指定がなければ `書籍/` 全体。

## フォルダ設計の原則(この基準で分類する)
1. **2桁番号+アンダースコア**でフォルダ名を統一する(例: `01_AI・プログラミング`)。番号は「仕事に効く順」— ユーザーの3つの目的(1:個人事業主の思考方法 / 2:商品開発・マーケティング / 3:AI能力の引き出し方。`KNOWLEDGE_PROFILE.md` 参照)に直結する棚を若い番号にする。
2. **深さは2階層まで**(`書籍/01_xxx/` で止める。その下にサブフォルダを掘らない)。
3. **1フォルダ100冊を超えたら分割**を提案する。
4. **本以外のファイル**(レシート・スキャン資料等)は `書籍/` の外(例: `資料/`)への移動を提案する(自動では動かさず、ユーザーに確認する)。

## ファイル名の原則(やりすぎない)
- **基本はリネームしない**(書名が入っていれば十分。検索性は知識ノート側の frontmatter/INDEX/recall で担保する)。
- リネームを提案するのは次の3パターンのみ:
  1. 分割PDF → `書名_1of3.pdf` 形式に統一
  2. 先頭の通し番号・スキャナが付けたゴミ文字列の除去
  3. 移動先での同名衝突 → `_著者名` を付加
- macOSの日本語ファイル名は文字正規化(NFD/NFC)の罠があるため、検索・比較にはワイルドカードや `ls` の実出力を使う(`grep 日本語` に頼らない)。

## 手順
1. **スキャン**: `書籍/` 以下を走査し、フォルダごとのファイル数・拡張子の内訳を把握する(`ls`/`find` を使用。読み取りのみ)。
2. **参照の把握**: `knowledge/BACKLOG.md`・`knowledge/INDEX.md`・`knowledge/*.md` の frontmatter(`出典書籍`)を読み、書籍パスを参照している箇所を洗い出す(移動後に更新するため)。
3. **分類計画の作成(ドライラン)**: 上記の原則に沿って「現在のパス → 移動先パス」の対応表を作り、`書籍/_整理計画.md` に保存してユーザーに提示する。
   - 迷う本(複数ジャンルにまたがる等)は「要確認」として別枠にまとめ、ユーザーに判断を仰ぐ。
   - リネーム提案がある場合は理由を添える。
4. **承認を待つ**: ユーザーが計画を承認するまで移動しない。修正指示があれば計画を直して再提示する。
5. **実行**: 承認後、`mkdir -p` + `mv` で移動する。
   - **削除は絶対にしない。上書きもしない**(移動先に同名ファイルがあればスキップして報告)。
   - `書籍/`(と承認された移動先)以外の場所には触れない。
6. **移動ログの保存**: 実行した全移動を `書籍/_整理ログ.md` に「日付 / 旧パス → 新パス」形式で追記する(元に戻せるように)。
7. **参照パスの更新**: 手順2で見つけた `knowledge/BACKLOG.md`・`knowledge/INDEX.md`・各ノートの `出典書籍` のパスを新パスに置換する。
8. **報告**: 移動件数・スキップ(衝突等)・要確認として残った本・更新した参照ファイルを要約する。空になった旧フォルダは報告のみ(削除はユーザーに委ねる)。

## 推奨する棚構成(初期提案のたたき台。実際のスキャン結果に合わせて調整する)
```
01_AI・プログラミング / 02_IT基盤・セキュリティ / 03_デザイン・クリエイティブ /
04_ビジネス・マーケティング / 05_仕事術・思考整理 / 06_金融・資産 /
07_健康・医療 / 08_科学・数学 / 09_人文・歴史・世界 / 10_語学 /
11_教養・趣味 / 12_小説 / 13_教科書・放送大学
```

## 注意
- 承認前の移動・リネーム・削除は厳禁。計画(ドライラン)と実行を必ず分ける。
- 一度に全部やろうとしない。フォルダ数が多い場合は「まず最大のフォルダ(例: PC・デザイン)だけ」など段階実行を提案してよい。
- 移動ログ(`書籍/_整理ログ.md`)を書く前に `mv` を始めない(ログ追記→移動の順でも、移動→即ログでもよいが、ログなしの移動を残さない)。
- 書籍PDF本体は Git 管理外(`.gitignore` 済み)。この整理はローカルのファイル操作であり、コミット対象は参照を更新した `knowledge/` 配下のみ。
