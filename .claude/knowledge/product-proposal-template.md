# 商品提案書の型（テンプレート）— 参考資料からの学習ノート

新商品候補を検討・提案するときの標準フォーマット。参考としてもらった実例
（Amazon新商品提案「オープンラック（4段/60cm天板）」全7スライド）から構造を抽出したもの。
チームが商品候補を提案するときは、**この7章構成で** アウトプットする。
`market-researcher` / `product-planner` / `china-sourcing-expert` / `data-analyst` が連携して埋める。

---

## 提案書の7章構成

### ① 商品概要 / 想定月間販売数
- 対象商品と投入仕様を1行で明確に（例：「4段／60サイズ天板で投入したい」）。
- ライバル数社の販売価格を並べる（例：¥11,988 / ¥8,670 / ¥7,599…）。
- **想定月間販売数と想定月間売上**を大きく提示（例：200〜400台/月、200〜400万円/月）。
  - 算定根拠を明記：「同サイズ商品の販売実績ベース／最も売れているライバル1SKU実績を参考算定」。
- 市場の定性コメント：「価格の高低に関わらず市場として売れている」「LPのレベルが全体的に低い、中国人セラーが多い」など**勝ち筋の観察**。

### ② 利益率・初期投資シミュレーション
- **粗利と利益率の試算**：想定販売価格 −（商品原価＋Amazon手数料＋国際送料＋国内送料）＝ 粗利/台と利益率。
  - 実例：販売¥6,180 − 原価71.3元(¥1,711) − Amazon手数料¥1,020 − 国際送料¥700〜800 − 国内送料¥1,150(140サイズ) ＝ 粗利¥1,200〜1,300（**利益率20%**）。
  - 月間粗利レンジも提示（例：販売200〜400台ベースで **24〜52万円/月**）。
- **初期投資**：初回発注数量（例：100台）と初回仕入れコスト（国際送料込み、例：24〜25万円）。「抑制投資×販売計画」の方針を明示。
- **工場からの情報**を箇条書きで添付：取扱説明書の付属可否／外箱カスタマイズの最低ロット（例：200個から）／生産納期（例：200個あたり7日）／最小ロット／特記事項（仕様変更の可否・傷や損傷時の全額返金対応など）。

### ③ 競合比較表（自社＋主要4社程度）
- 行：画像／ブランド名／価格（通常＋セール時）／ランキング／色／材質／付属品／特徴・キャッチ／**肯定的評価**／**低評価**。
- 自社列には投入予定の差別化を記載（例：「競合より抑えた価格・画像クリエイティブで差別化・フック付き」）。
- 実際のライバルが10社以上いる場合も、代表的な4〜5社に絞って深く比較する。

### ④ 競合レビューから見える改善ポイント
- 競合レビューを横断分析し、**低評価につながる要因を3〜4つ**の ISSUE として整理。各 ISSUE に改善策をセットで書く。
- 実例：
  - ISSUE1 サイズ感のミスマッチ → 冷蔵庫などと並べた**比較画像**を掲載し購入前後のギャップを最小化（低レビュー防止）
  - ISSUE2 説明書がわかりにくい → 組立工程を明確化、**全工程の説明動画（QRコード）**、1人組立を支援する表現
  - ISSUE3 木材の傷（低レビューの直接原因）→ 工場側に**傷最小化を打診**、傷あり時の**全額返金**を取付
  - ISSUE4 脚部組立の難しさ → 接合方式を**ネジ式へ変更**を交渉（追加コスト無しで対応可能）

### ⑤ 工場打診結果 / 改善案ステータス
- レビュー分析から出た改善案を**工場に打診した結果**を「判定／改善案／工場からの回答／懸念事項」の表で管理。
- 判定は「対応可／要確認／不可」の3段階。
  - 実例：ネジ式変更＝対応可（当初+5元→交渉で価格変更なし）／傷の最小化＝要確認（全額返金というが定義の認識違いに懸念）／脚の取付済み発送＝不可（水平の保証ができないため許容）。
- **交渉の途中経過と残リスクを隠さず書く**のがポイント（オーナーが判断できる）。

### ⑥ 今後の展開
1. **価格戦略**：競合より抑えた価格設定（例：ライバル¥7,599〜11,988に対し¥6,180想定）。ライバルの画像が弱い→クリエイティブで集客強化。
2. **商品提案/SKU展開**：初期は最も売れているサイズ・段数から開始 → 段数・サイズ・**他社にないカラー展開**でSKU拡大 → 親ASIN全体の月間販売金額を底上げ。キャスター移動タイプ・強度フック・ブックスタンド等の**付属品で独自性**。
3. **販促活動**：利用シーン訴求を全面展開。サイズ感を画像で分かりやすく伝え、購入前後のギャップ最小化 → **低レビュー予防**。
4. **在庫管理**：工場の生産納期と海上輸送日数を考慮した在庫設計。在庫切れを起こさない徹底管理。

### ⑦（運用）数値の検証
- 想定販売数・利益率は投入後に実データで検証し、提案書を更新する。

## この型の使い方（チーム運用）

- オーナーが「この商品どう？」と聞いたら、司令塔が各専門家に分担させ、**この7章で1本の提案書に統合**する。
  - ①③④ market-researcher ／ ② accountant・data-analyst ／ ②⑤ china-sourcing-expert ／ ④⑥ product-planner・creative-designer・marketing-specialist ／ ⑥-4 inventory-manager・global-logistics-expert
- 保存先は `docs/商品提案/<日付>_<商品名>.md`。
- 判断基準は既存プレイブックを適用：利益率30%目標（参考例の20%は「初期は20%以上でも可」の範囲）／
  デカ重5チェック（`amazon-dekajuu-playbook.md`）／低評価レビュー→改善仕様（`amazon-oem-playbook.md`）。

> 学び：この参考例は「**リサーチ→利益計算→競合比較→レビュー改善→工場打診→展開計画**」が1本の流れに
> なっている。つまり提案書とは、プレイブック群の実行結果を**オーナーが投資判断できる形**に束ねたもの。
