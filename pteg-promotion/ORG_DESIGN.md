# 組織設計書 — PTEG学術集会プロモーションチーム

作成: 2026-09-03 / 決定者: 社長(ユーザー)
社長の指示——「私が社長」「適切な部署はAIが設計」「副社長に批判的に意見できるAIを置く」
「分析・評価・比較をして提案」「成果物を常に改善する仕組み(PDCA)」「指示より良い案があれば提案」
「新しい挑戦をする仕組み」——に基づく設計と、代替案の比較・採用理由の記録。

## 1. 設計要件(社長の指示の分解)と実装
| 要件 | 実装 |
|---|---|
| 社長=ユーザーが最終決定 | すべての提案は「社長の決定が必要な事項」を明示して終わる。チームは決定しない |
| 批判的に意見できる副社長 | `pteg-vice-president` を全成果物の必須検証ゲートに。加えて**対案提出義務**を課す |
| 適切な部署 | 機能別6部署+統合・改善の2役(§3) |
| 分析・評価・比較 | `pteg-insight-analyst`(比較評価の専任)+全部署に「複数案+比較+推奨」を義務化 |
| PDCA | PROMO_DECISION_LOG(P) → 実行(D) → `/pteg-review`(C) → PROMO_LESSONS(A)の学習ループ |
| 指示より良い案の提案 | 上申ルール: 指示通り案と対案を並記して提案する義務(全部署+副社長)。最終決定は社長 |
| 新しい挑戦 | 挑戦枠の義務化(毎提案に最低1件)+ CHALLENGES.md + `pteg-innovation-lead` |

## 2. 組織案の比較(分析・評価・比較)
3案を設計し、評価軸を明示して比較した。

- **案A: 機能別部署+独立検証ゲート型(採用)** — 戦略/広報/制作/参加者体験/分析/挑戦の機能別6部署に、独立した副社長ゲート・事務局長・PDCA担当を置く。
- **案B: 少数精鋭型** — 企画(1)・批判(1)・統合(1)の3エージェントのみ。
- **案C: チャネル班型** — Web班・SNS班・紙媒体班・動画班などチャネル単位の編成。

| 評価軸 | 案A 機能別+ゲート | 案B 少数精鋭 | 案C チャネル班 |
|---|---|---|---|
| 検討の網羅性・専門性 | ◎ 機能ごとに深掘り | △ 1役が全部担い浅くなる | ○ チャネルは深いが戦略が薄い |
| 批判機能の独立性 | ◎ 専任+義務化 | ○ 専任だが対象が広すぎる | △ 班同士の相互批判は甘くなる |
| 実行コスト(API・時間) | △ フル起動は高い | ◎ 安い | ○ 中 |
| PDCA適合 | ◎ 記録と改善の専任あり | △ 兼任で形骸化しやすい | △ 記録が班別に分散 |
| 挑戦の生まれやすさ | ◎ 専任部署+義務化 | △ 定番に流れやすい | △ 既存チャネルの最適化に閉じる |
| 拡張性(次回大会・別事業) | ◎ 機能は使い回せる | ○ | △ チャネル構成に依存 |
| 意思決定の速さ | ○ 要点集約で担保 | ◎ | ○ |

**評価**: 案Bはコスト最小だが、「批判・比較・挑戦を制度として回す」という社長の要件を
1エージェントの注意力に依存させることになり、要件適合で劣後する。案Cは実行段階では有効だが、
「誰に何を伝えるか」より先に「どの媒体でやるか」が決まる本末転倒が起きやすい。
**案Aを採用**し、コストの弱点は**軽量モード**(テーマ指定時は関連部署のみ起動。ただし副社長ゲートは
省略不可)で補う。チャネル別の作業単位が必要になったら、広報・マーケ部の中の班として扱う
(案Cの長所を吸収)。

## 3. 採用した組織
```
社長(ユーザー) — 最終意思決定
 └ 副社長 pteg-vice-president — 批判的検証ゲート+対案上申(全成果物が必ず通る)
    ├ 戦略企画部          pteg-strategy-planner   (戦略・ターゲット・KPI・逆算スケジュール)
    ├ 広報・マーケティング部 pteg-marketing-pr       (チャネル計画・告知カレンダー)
    ├ クリエイティブ制作部   pteg-creative-director  (コピー・文面・制作指示書)
    ├ 参加者体験部         pteg-engagement-lead    (演題募集・参加登録・多職種/若手)
    ├ 分析評価部          pteg-insight-analyst    (ベンチマーク・比較評価・測定設計)
    ├ 挑戦・イノベーション部  pteg-innovation-lead    (挑戦枠の実験設計・事例輸入)
    ├ 事務局長(統合編集)    pteg-secretariat        (統合・提案書化・ログ記録)
    └ PDCA・改善担当       pteg-kaizen-reviewer    (実績照合・教訓蓄積・組織改善)
```

### 使用モデル(2026-09-03 社長指示)
- **副社長: Fable(上位モデル)** — 全成果物が通る検証ゲートであり、チームで最も重い判断
  (批判の質・見落とし検出・対案の質)を担うため、社長指示により上位モデルを充てる。
- その他の部署: Sonnet(コストと品質のバランス)。必要になれば部署単位で見直す(社長決定)。

## 4. 社長の指示に対する設計上の追加提案(採用済み。変更は社長判断)
指示を実装する過程で、指示のままより良いと考えた点を以下のとおり組み込んだ。
不要なら外すので指摘いただきたい。

1. **副社長に「対案提出義務」を追加**: 「批判できる」だけだと差し戻しばかりで前に進まない。
   批判には必ず対案か補強要求を添える義務を課した。
2. **批判(事前)と振り返り(事後)を分離**: 副社長=実行前の検証、PDCA担当=実行後の検証。
   同じ役が両方を担うと、事前の自分の判断を事後に甘く裁くバイアスが生じる。
3. **挑戦枠の義務化+撤退基準の事前設定**: 「挑戦する仕組み」を掛け声で終わらせず、
   提案書の必須セクション+記録簿(CHALLENGES.md)+撤退基準の事前定義で制度にした。
4. **却下された対案も記録**: 上申が却下された場合も PROMO_DECISION_LOG.md に残す。
   後から対案が正しかったと分かることが最大の学習機会になる。
5. **組織自体をPDCAの対象に**: `/pteg-review` は施策だけでなくエージェント定義・手順の改訂も
   提案する(適用は社長の承認後)。
6. **軽量モード**: フル起動はAPIコストが高いため、スコープ指定時は関連部署のみ起動する。
   ただし副社長ゲートだけはどのモードでも省略しない。
7. **医療学会広報の品質基準を共通化**: 正確性・品格・表現ルール遵守(玉ねぎ不使用・ポスター改変禁止・
   AI文字生成禁止 等、既存ポスター/動画指示書のルールを継承)を全部署共通の心得+副社長のチェック項目にした。
