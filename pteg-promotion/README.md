# PTEG学術集会 プロモーションチーム 運用マニュアル

第25回 日本PTEG研究会 学術集会(2027年9月12日(日)・札幌市教育文化会館、テーマ「地域・PTEG・ケアの近未来」)の
プロモーションを企画・制作・改善するAIエージェント組織の使い方。
組織設計の経緯と代替案の比較は `ORG_DESIGN.md` を参照。

## 組織図
```
社長(ユーザー) — 最終意思決定
 └ 副社長 pteg-vice-president — 批判的検証ゲート+対案上申(全成果物が必ず通る)
    ├ 戦略企画部          pteg-strategy-planner
    ├ 広報・マーケティング部 pteg-marketing-pr
    ├ クリエイティブ制作部   pteg-creative-director
    ├ 参加者体験部         pteg-engagement-lead
    ├ 分析評価部          pteg-insight-analyst
    ├ 挑戦・イノベーション部  pteg-innovation-lead
    ├ 事務局長(統合編集)    pteg-secretariat
    └ PDCA・改善担当       pteg-kaizen-reviewer
```

## コマンド
| コマンド | 何をするか |
|---|---|
| `/pteg-plan [テーマ]` | 企画提案書を作成(部署並行→副社長検証→事務局長統合→`proposals/`へ)。テーマ指定で軽量モード |
| `/pteg-review [実績データ]` | PDCAのCheck→Act。実績照合・教訓蓄積・挑戦判定・組織改善提案 |
| `/pteg-challenge [テーマ]` | 挑戦枠のアイデア補充(イノベーション部→副社長リスク検証→`CHALLENGES.md`へ) |

## ファイル
| ファイル | 役割 |
|---|---|
| `PROMO_PROFILE.md` | 開催概要・ストーリー・**表現ルール**・ターゲット。全部署が作業前に必読 |
| `ORG_DESIGN.md` | 組織設計の分析・比較・決定の記録 |
| `PROMO_DECISION_LOG.md` | 提案と社長決定・KPI・検証予定の記録(PDCAのP) |
| `PROMO_LESSONS.md` | 蓄積された教訓(全部署が作業前に必読) |
| `CHALLENGES.md` | 挑戦のバックログと実験記録 |
| `proposals/` | 企画提案書の保存先 |
| `deliverables/` | 制作物ドラフト(文面・制作指示書)の保存先 |

## 4つの仕組み
### 1. 副社長ゲート(批判の制度化)
すべての提案・制作物は社長に届く前に副社長の批判的検証を通る。副社長は批判だけでなく
**対案の提出義務**を負い、社長の指示そのものにも上申できる(最終決定は社長)。

### 2. 上申ルール(指示より良い案の提案)
全部署共通: 社長指示より良い方法があると考えたら、指示通り案と対案を並記して比較つきで上申する。
勝手に置き換えない。却下された対案も記録する(後から対案が正しかったと分かるのが最大の学習機会)。

### 3. PDCA(成果物を常に改善する仕組み)
- **Plan**: `/pteg-plan` → 提案書+KPI+反証条件を `PROMO_DECISION_LOG.md` に記録
- **Do**: 社長・事務局が実行(制作物ドラフトはチームが用意)
- **Check**: `/pteg-review` → 実績データと見立てを照合
- **Act**: `PROMO_LESSONS.md` を更新 → 次の `/pteg-plan` で全部署が必ず読む
組織自体(エージェント定義・手順)もPDCAの対象で、改善案は社長の承認後に適用する。

### 4. 挑戦枠(新しい挑戦をする仕組み)
毎回の企画提案書に、**仮説/実験/成功基準/撤退基準**つきの挑戦を最低1件含める(なければ未完成扱い)。
記録しない失敗は禁止。判定(拡大/継続/撤退)は社長が行う。

## 運用メモ
- サブエージェント多数+Web検索のため、フル起動の `/pteg-plan` は実行ごとにAPI利用料がかかる。
  部分的な相談はテーマ指定の軽量モード(例: `/pteg-plan 演題募集の告知だけ`)で。
- このチームの成果は情報整理・企画支援であり、医学的内容の最終確認は世話人・事務局が行う。
- 未確定情報(`PROMO_PROFILE.md` §7)が埋まるほど提案の精度が上がる。
